## 真实 Telegram 已验证的范围

- 三份隔离 Session 副本认证成功，并各自加入指定测试群一次；源文件保持原样。
- 两个服务账号通过真实 gateway HTTP 连接。第三个账号保留为外部触发者，尚未连接到业务后端。
- G2 精确发送一条标记消息、一次 POST、零重发。202 受理、唯一发送回执、两个在线服务账号下唯一 own 消息、按 clientMsgId 查询、原 eventId 重连补拉、独占游标无重复，八项检查通过。
- 首次组合尝试发送一条外部触发，Telegram 确认已发送；80 秒内后端入站、Agent run 和回复均为零。脚本关闭 Agent/auto-kick 并保留失败证据。旧 G3 网关后来被动补入该消息，不能把迟到补拉或 G2 own 回执当作正常实时入站通过。
- G4 修复 hash-only/零 pts 初始化后，三个账号均取得有效频道游标；网关从有证明的连续 exact-ID 边界核对历史，缺乏旧证据时从 ID1 开始。不可取得的旧内容与历史成员状态限制明确记录为 recovered_with_limits。Agent 全程关闭，原触发消息在后端唯一、非 own，且无 pending/run。
